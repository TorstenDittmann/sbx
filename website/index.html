The SQLite of sandboxes.

Run untrusted code on a machine you already have. sbx serve starts a sandbox API in front of Docker. Network is off, the clock is short, and the same calls still work when you later turn the dial toward gVisor, microVMs, or a cluster.

Start a sandbox Read the source

One process

A Go binary, a SQLite file, and the Docker socket. No Postgres, Redis, or Nomad until you actually outgrow a single host.

Closed by default

Sandboxes drop every capability, run as uid 1000, use a read-only rootfs, and have no network. A server-side reaper enforces the TTL.

A small API

Create, exec, files, terminals, and preview URLs over /v1. curl works. The TypeScript SDK works on Node and Bun. OpenAPI is served from the process itself.

Install a release.

A version tag publishes the binary, the container, and the TypeScript package. The source quickstart is still below.

curl -fsSL https://raw.githubusercontent.com/TorstenDittmann/sbx/main/install.sh | sh
sbx version

docker run --rm -p 8080:8080 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v sbx-data:/data \
  ghcr.io/torstendittmann/sbx:latest

npm install @sbx.torsten.work/sbx
bun add @sbx.torsten.work/sbx

Linux installs sbx and sbx-agent. macOS installs the darwin server and the linux agent, because the agent runs in the container. The image already contains both and sets SBX_AGENT_BIN. The npm name sbx is a different project; this package is @sbx.torsten.work/sbx.

Two commands, then a curl.

Docker has to be running. The first boot prints an admin key once and writes it to data/initial_api_key.

go build -o sbx ./cmd/sbx
./sbx serve

curl -s http://127.0.0.1:8080/v1/sandboxes \
  -H "Authorization: Bearer $SBX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"template":"base"}'

curl -s http://127.0.0.1:8080/v1/sandboxes/$ID/exec \
  -H "Authorization: Bearer $SBX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"cmd":["echo","hello"]}'

Prefer the SDK: set SBX_URL and SBX_API_KEY, then node --experimental-strip-types examples/quickstart.ts. Built-in templates are base, python, and node.

Isolation is a setting.

The default backend is Docker. gVisor is the same driver with the runsc runtime, when that runtime is registered. The later rungs are the same API, not a different product.

  1. 0 · now

    docker

    Namespaces and cgroups. The default, because it starts on a laptop that already has Docker.

  2. 1 · optional

    gvisor

    Select "backend": "gvisor" after runsc is a Docker runtime. No KVM required. Missing runtime is a clear error, not a silent fallback.

  3. 2 · later

    kata / firecracker

    A VM per sandbox when a shared kernel is not enough. The driver interface is the slot they plug into.

  4. 3 · later

    cluster

    The same binary grows a controller and nodes. SQLite stays the single-host store. Postgres shows up only then.

The calls you actually make.

Auth is Authorization: Bearer sbx_…. Keys are stored hashed. A sandbox key only sees its own sandboxes.

import { Sandbox } from "@sbx.torsten.work/sbx";

const box = await Sandbox.create({
  template: "python",
  ttl: "5m",
});

await box.files.write("/workspace/main.py", "print(2 + 2)\n");
const result = await box.exec(["python", "main.py"]);
console.log(result.stdout);
await box.kill();
  • POST /v1/sandboxescreate
  • POST /v1/sandboxes/{id}/execwait, or SSE with ?stream=1
  • POST /v1/sandboxes/{id}/terminalsPTY, then a WebSocket
  • POST /v1/sandboxes/{id}/previewsreach a port inside the sandbox
  • PUT /v1/sandboxes/{id}/files/contentupload
  • GET /healthzDocker reachable?
  • GET /openapi.yamlthe contract

What this release does not pretend.

  • network: full can reach the public internet, and still cannot reach cloud metadata or private and link-local ranges. Egress allow-lists are rejected.
  • Disk limits are the size of the writable /workspace tmpfs. The root filesystem is read-only.
  • sbx-agent runs inside the sandbox, so exec, files, terminals, and previews do not need a shell in the image. Archives still call tar. Without the agent binary, those new routes answer unsupported and exec stays on the shell path.
  • Pause, resume, templates, quotas, and Prometheus metrics are real. Egress allow-lists and a multi-node scheduler are not in this release. Kata, Firecracker, and Kubernetes are the same API later.
